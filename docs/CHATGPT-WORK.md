# ChatGPT Work / Project Design Guidelines

Use this file in a ChatGPT Project or Work workspace alongside a copy of the
site's active `design-system/MASTER.md`.

## Required behavior

For significant website UI/UX/frontend design work:

1. Read the site's design system first.
2. Preserve approved branding unless the user explicitly requests a redesign.
3. Determine `EVOLVE` vs `REDESIGN`.
4. Understand purpose, audience, and conversion before designing.
5. Inspect existing components/pages when context is available.
6. Define a compact visual thesis before substantial implementation.
7. Reject generic AI-looking patterns not justified by the brand.
8. Treat responsive, accessibility, and performance as design constraints.
9. Critique the visual result before considering it complete.

## Authority

1. Current user request
2. Existing approved brand
3. Active design system
4. Page-specific decisions
5. Existing component language
6. These guidelines
7. Generic UX conventions/trends

## Anti-generic gate

Question:
- Could this belong to almost any company?
- Is the design defaulting to cards?
- Is a bento grid arbitrary?
- Are gradients/glass/blobs/glows meaningful?
- Are pills/badges meaningful?
- Is decorative numbering pretending order exists?
- Is oversized type hiding a weak idea?
- Is motion useful?
- Is copy specific?

Revise when the answer reveals generic or unjustified choices.

## Responsive review

Check around:
- 375px
- 768px
- 1024px
- 1440px

Do not simply shrink desktop.

## Definition of done

Design work should preserve brand coherence, clarify the page job, work on mobile
and desktop, address obvious accessibility/performance concerns, and survive a
visual self-critique.

## Objective

Build an SEO structure that:
- helps the correct audience understand Laure's offers;
- preserves the brand vocabulary;
- captures relevant service/informational intent;
- avoids unsupported health/spiritual claims;
- avoids page cannibalization;
- remains useful even without search traffic.

SEO does not get permission to invent service details.

---

# 1. Intent ownership

Each important intent should have one clear canonical destination.

## Brand / umbrella

Homepage:
- Le Moulin de Laure
- brand discovery
- broad overview

Do not make the homepage compete aggressively with the dedicated “communication animale” page for the full generic service query.

## Service intent

One detail page per accompaniment:
- Communication animale
- Accompagnement énergétique animalier
- Connexion avec les défunts
- Guidance pour soi

## Comparison / orientation

Accompagnements hub:
- helps users understand the four paths;
- not a duplicate of all four detail pages.

## Informational

FAQ + Journal:
- questions;
- explanation;
- long-tail intent;
- internal linking.

## Navigational / trust

- À propos
- Contact
- Prendre rendez-vous
- Le Jardin

# 3. Cannibalization rules

## Homepage vs Communication animale

Homepage:
brand/umbrella.

Communication page:
owns the generic service query.

Do not place an enormous SEO definition of communication animale on home.

## FAQ vs detail page

Detail page:
primary service explanation.

FAQ:
answers questions and links back to the detail page.

## Journal vs service page

Articles should answer one narrower question and link to the relevant service page.

Do not publish an article with the same title/intent as an existing service page.

## Accompagnements

Links to all four detail pages.

Each links to:
- Accompagnements;
- booking;
- FAQ;

- other accompaniments at the bottom.

## About

Links naturally to:
- Communication animale;
- Accompagnements.

## Journal

- one main related service destination;
- contextual links;
- 2–3 genuinely related articles where available.

## FAQ

Anchor text should be natural/descriptive, not stuffed.

# 5. Technical SEO

## Rank Math

Use Rank Math as the primary SEO metadata/canonical/sitemap layer unless a specific project feature requires otherwise.

Avoid duplicate schema from:
- Rank Math;
- theme;
- Structured FAQ plugin;
- custom code.

## XML sitemap

Include:
- homepage;
- indexable core pages;
- Journal articles.

Exclude:
- thank-you page;
- booking confirmation/cancellation pages;
- internal search results;
- thin/empty archives;
- any private/draft content.

## noindex

Use meta noindex for:
- `/merci/`
- `/reservation-confirmee/`
- `/reservation-annulee/` if used
- search-result pages
- thin archive types not used by the editorial strategy.

Do not rely on robots.txt for noindex.

## WordPress archives

At launch, unless real strategy changes:
- tag archives: noindex/disabled;
- author archive: noindex or redirect if Laure is the only author and no unique value exists;
- date archives: noindex/disabled;
- categories: do not expose until useful;
- media attachment pages: redirect/noindex according to Rank Math setup.

## Canonicals

Self-canonical all indexable pages.

Booking:
keep `/prendre-rendez-vous/` as the canonical public booking URL.

Do not allow Timetics/embed variants to become competing indexable URLs.

## Breadcrumbs

Use consistent hierarchy:
Home > Accompagnements > [service]

and:
Home > Journal > [article]

Breadcrumb markup can be generated by one coherent source.

# 6. Structured data

## Site / business

Prefer one coherent Rank Math configuration for:
- Organization or appropriate entity type;
- website/site name;
- logo.

Do not invent LocalBusiness data until physical/public location and business details are confirmed.

## BreadcrumbList

Useful on hierarchical pages.

## BlogPosting / Article

Use on Journal articles with:
- headline;
- image;
- datePublished;
- dateModified;
- real author.

## FAQ

Visible FAQ remains useful.

FAQ rich results are deprecated/removed in Google as of 2026.

If FAQPage schema is kept for semantic reasons:
- only one plugin/source outputs it;
- visible answer text must match;
- do not expect SERP accordion benefit.

Do not use `QAPage` for the site's own FAQ.

## Service schema

Optional semantic markup only if cleanly supported by Rank Math/custom code.

Do not add schema merely because it exists; there is no direct Google rich-result reason to over-engineer Service markup here.

# 7. Content quality / authorship

Journal content should show real authorship.

Recommended:
- byline: Laure Moulin when she actually authors/reviews/owns the content;
- author link to About;
- accurate datePublished;
- dateModified only for substantial updates.

AI can assist drafting/research internally, but:
- no mass publication;
- human/client review required;
- no invented experience;
- no fabricated sources/credentials;
- no artificial “freshness” date changes.

# 8. Health / sensitive-topic rules

This project touches:
- animal wellbeing;
- energy practices;
- grief/deceased topics.

Content must be especially careful.

Never:
- diagnose;
- promise healing;
- claim veterinary efficacy;
- imply certainty about deceased contact;
- exploit grief;
- target fear-driven symptom keywords with unsupported claims.

On relevant animal pages:
make the veterinary boundary visible.

---

# 9. Image SEO

Original paintings are a differentiating asset.

For public derivatives:
- readable descriptive filenames;
- optimized WebP/AVIF where appropriate;
- responsive `srcset/sizes`;
- explicit width/height/aspect ratio;
- alt text based on actual image purpose;
- no keyword-stuffed alt text;
- nearby text that explains the universe/service.

Do not expose original full-resolution client source unnecessarily.

After launch, monitor Google Search Console's image/multimodal performance where data exists.

---

# 10. Local SEO

Do **not** create city landing pages until Laure's real:
- location;
- service area;
- presentiel conditions

are confirmed.

No “communication animale Paris/Lyon/…” programmatic pages.

If Laure has an eligible public/local practice:
- configure Google Business Profile;
- use consistent business data;
- then assess local landing needs based on real geography.

Remote availability should be described accurately without creating fake local presence.

Start small.

Initial cluster priority should come from real questions Laure can answer from first-hand practice.

Strong source/SERP-aligned starting topics:
- Qu'est-ce que la communication animale ?
- Comment se déroule une communication animale ?
- Communication animale à distance : comment cela se passe ?
- Pourquoi faire une communication animale ? — only with Laure's approved examples
- Quel est le cadre d'une communication animale par rapport au vétérinaire ?

Possible future clusters, only after service detail is supplied:
- accompagnement énergétique animalier;
- connexion avec les défunts;
- guidance pour soi.

Do not launch 20 thin articles simply because keywords exist.

# 12. Post-launch measurement

Google Search Console:
- submit sitemap;
- inspect core URLs;
- monitor indexing;
- monitor queries/page cannibalization;
- monitor image/multimodal performance;
- review CTR/title rewrites;
- identify real long-tail FAQ/Journal opportunities.

Analytics:
- accompaniment page -> booking click;
- booking completion if privacy-consent/config supports it;
- contact submissions;
- Journal -> service click.

SEO decisions after launch should be based on observed data, not just pre-launch assumptions.

# WordPress Web Design Rules

Use these rules for WordPress sites in addition to the general design workflow.

## Architecture

Prefer, in order:

1. Existing theme settings/tokens when they cleanly solve the requirement
2. Child-theme templates and assets
3. Reusable child-theme components/partials
4. Approved custom plugin for behavior/content features
5. Carefully scoped CSS/JS overrides

Never modify WordPress core for design work.

## Astra and similar themes

When a parent theme controls:
- fonts
- container widths
- header
- breakpoints
- global colors
- button styles

inspect those settings before adding overrides.

Do not create a competing design system accidentally.

## CSS

Before adding a rule:
- search for the existing selector/component
- identify cascade/specificity
- prefer reusable component classes
- avoid repeated page-ID rules
- avoid `!important` unless genuinely necessary
- avoid broad selectors that affect admin/editor/plugin UI

Keep mobile behavior explicit.

## PHP/templates

Before editing:
- identify child-theme override mechanism
- preserve hooks and required wrapper markup
- preserve escaping/sanitization
- avoid changing unrelated behavior

After editing:
- run `php -l` when available
- inspect errors/logs if a failure occurs
- verify page status

## JavaScript

Prefer progressive enhancement.

For filtering/navigation/forms:
- preserve real links/forms when possible
- maintain browser history where relevant
- avoid breaking keyboard use
- handle failed requests gracefully

Do not add a heavy JS dependency for a small visual effect.

## Images and performance

Hero/LCP:
- avoid lazy-loading the actual LCP image
- set intrinsic dimensions where possible
- use appropriate responsive sources
- use `fetchpriority` only where justified
- avoid multiple high-priority images

Below-the-fold:
- lazy-load appropriately
- compress/resize images

Avoid CSS backgrounds for important content images when responsive image semantics matter.

## LiteSpeed/cache/CDN

After meaningful frontend changes:
- account for cache when verifying
- do not diagnose cached output as current code without checking
- purge only the necessary cache scope when possible

Do not alter cache settings casually during a design task.

## Rank Math / SEO

Design changes must preserve:
- one coherent page H1
- meaningful heading hierarchy
- structured content
- canonical/navigation behavior
- schema generated by existing plugins unless intentionally changed

Do not add duplicate schema merely for design purposes.

## TranslatePress/localization

Do not rely on:
- fixed text lengths
- line breaks inserted for one language
- layouts that fail with longer translated labels

Ensure interactive labels remain understandable in all target languages.

## Accessibility

Respect WordPress/plugin semantics where they are already correct.

Do not replace native buttons/links with non-semantic divs for styling convenience.

## Production safety

Prefer:
- Git
- diffs
- small changes
- syntax validation
- rollback path

Avoid editing production without a recoverable copy of critical files.
